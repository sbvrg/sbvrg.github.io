Building

nasm: No such file or directory. The boot code and the bootloader are written for nasm, and the build stops at the first .asm file without it. Install nasm and run make again (development).

grub-mkrescue: command not found. grub-mkrescue comes with sys-boot/grub. It also needs xorriso, which is in app-cdr/libisoburn. make still builds the kernel without them, and only make iso needs them.

QEMU says the ISO isn't bootable. grub-mkrescue only includes the GRUB platforms that are installed. If only the EFI modules are present, the ISO has no BIOS boot record, and QEMU's default BIOS can't start it. Install the i386-pc modules and rebuild the ISO.

The docs check prints problems. Every built-in word needs a help entry with a stack effect and an example, and the check compares the two. The output names the word and the entry that is missing or doesn't match (development).

Booting

A black screen, or "No bootable device". A blank disk image is attached, and QEMU tried it before the CD. Add -boot d to boot from the CD first.

A GRUB prompt instead of Subverge. GRUB didn't find its configuration. Type multiboot /boot/subverge.elf, press Enter, then type boot.

The installed disk won't boot. Boot it with -hda disk.img and no -cdrom. If it still doesn't start, boot the ISO with the disk attached and run disks. The drive Subverge is installed on is marked with 1. If none is marked, install never finished, and running it again fixes it.

the saved root didn't build, using the built-in one. The root saved on the disk failed to build with the kernel that is running. This usually happens when an old disk is booted with a newer kernel and a unit uses a word that changed. Your tabs are still loaded. See root for how drafts and rebuilds work.

sys shows the old version after an upgrade. The kernel is new, but the root came from the installed disk, and that root has the old sys. See upgrading an installed disk.

Using it

The clock is wrong. The tab bar shows the time from the CMOS clock, and QEMU sets that clock to UTC by default. Add -rtc base=localtime to the QEMU command line to see local time.

No drives were found. The disk is attached as virtio or NVMe, and Subverge only has an IDE driver. Attach it with -hda instead.

Nothing is saved. You are on the live ISO, which keeps everything in memory. The welcome text says which one you are on. Install to a disk image to keep your work.

My whole line did nothing. A word on the line failed, so the line was undone, including the parts that ran before the failure. The red text says which word failed and why (transactions).

back went further than I expected. back only counts lines that changed something. A line that only printed, such as help, isn't counted, so back skips over it to the line before (back).

A word works at the prompt but not inside another word. Locals are dynamically scoped. A local in the calling word with the same name as a word you call hides that word, or a word you call reads a local you didn't mean to pass. Rename one of them (names).

forget says the name isn't defined in this tab. forget only removes definitions made in the current tab. A word defined in root has to be changed in root with 'name open (names).

My root edit didn't do anything. The edit didn't build, so root was left as it was and the edit was kept as a draft. root marks the unit (draft). Open it again with 'name open to see the error and fix it (root).

I used edit on top and the other tabs didn't change. edit redefines a word in the current tab only, which makes a private copy that hides the root version. Use 'top open to change root for every tab, and 'top forget to drop the private copy (scrawl).

My program isn't in apps. apps prints a fixed list. Add your program to it with 'apps open (apps).

The colours are unreadable. Switch back with 'dusk theme, or type themes to pick another (themes). In amber, phosphor and haelide every colour is a shade of one hue, so programs that rely on colour to tell things apart are harder to read in them.

My rgb colours are gone after a reboot. rgb changes the palette until the next theme switch or reboot, and isn't saved. Put the rgb lines in startup to apply them at every boot (themes).

The theme resets at every boot. You are on the live ISO, which always starts with dusk. An installed system keeps the theme.

sys shows the cat after I picked a logo. Either you switched themes, and the logo you picked had the name of the old theme, or the logo was defined in another tab. sys runs in tab 1 at boot, so put the logo in a root unit (logos).

Tab does nothing at the prompt. Nothing matches the name before the cursor, or the cursor is right after a space (prompt).

redo says nothing to redo. A line changed the world after the back, and that clears the redo list (back).

Ctrl-C doesn't stop it. The code is stuck in a place that doesn't check for Ctrl-C, such as a long built-in. Switch to another tab with F2 to F4, which keeps working (tabs).

Everything froze. Something wrote over memory the kernel uses, a port write hung the machine, or halt was run. Close QEMU and start it again. On an installed disk, every line up to the last one that succeeded was saved.
